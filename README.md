# Clipboard

原生 macOS 菜单栏剪贴板历史与长期收藏工具，基于 Swift、SwiftUI 与 AppKit 实现，仅依赖共享日志包 `kirktools/pkg-logging`（锁定于 `Package.resolved`）。默认界面语言为简体中文。

## 功能概览

- **最近历史**
  - 常驻菜单栏，自动记录纯文本、网页链接（`http`/`https`）和图片，重启后保留。
  - 默认保留最近 50 条（可在设置中调整为 10–500 条）；重复复制同一内容时更新最近时间并置顶，不产生重复记录。
  - 面板支持按文本、链接与条目名称实时搜索，图片显示缩略图与尺寸信息。
  - 键盘优先操作：`↑`/`↓` 选择，`↩` 复制回系统剪贴板并关闭面板，`⌘1`/`⌘2` 切换「最近 / 收藏」，`⌘D` 收藏或取消收藏，`⌘⌫` 删除，`Esc` 关闭。
- **长期收藏**
  - 最近记录可一键收藏；「收藏」有独立入口，支持改名、搜索、取消收藏和再次复制。
  - 收藏跨重启保留，不占最近历史条数；即使历史因上限被淘汰或用户清空最近，收藏条目及图片依然完整保留。
- **本地存储与隐私控制**
  - 数据仅保存在本机，不联网、不上报。
  - 提供「暂停记录」入口，暂停期间不写入新历史。
  - 自动跳过明确标记为敏感、临时或自动生成的剪贴板内容（如 `org.nspasteboard.ConcealedType`、`TransientType`、`AutoGeneratedType` 等）；不会假设可识别所有密码工具。
  - 兼容 macOS 15.4+ 剪贴板访问行为（`NSPasteboard.accessBehavior`），在设置中展示当前授权状态。

## 日常开发与构建

需要 macOS 14+ 与 Swift 6 / Xcode Command Line Tools。

```sh
make dev                         # 仅重启当前工作区的开发版 dist/dev/Clipboard Dev.app
make test                        # 运行单元测试与集成测试
make check                       # 脚本语法、Info.plist、diff 与编译检查（不启动应用）
make build                       # 仅构建开发版（CONFIG=debug）
make build CONFIG=release        # 仅构建发布版（dist/release/Clipboard.app）
make package                     # 生成本地 Release 安装包（DMG/ZIP/校验清单，不发布）
make release-dry-run BUMP=patch  # 仅预览 SemVer 递增与本地发布条件（不改文件、不联网）
```

静默常驻启动（仅驻留菜单栏，不弹出面板）：

```sh
open "dist/dev/Clipboard Dev.app" --args --background
```

### Dev 与正式版隔离

| 项目 | 正式版（Release） | 开发版（Dev） |
| --- | --- | --- |
| 应用包 | `dist/release/Clipboard.app` | `dist/dev/Clipboard Dev.app` |
| Bundle ID / 签名标识 | `dev.clipboard.app` | `dev.clipboard.app.dev` |
| 数据目录（设置/历史/收藏/图片） | `~/Library/Application Support/Clipboard/` | `~/Library/Application Support/Clipboard-dev/` |
| 诊断偏好域与日志目录 | `dev.clipboard.app` / `~/Library/Logs/Clipboard/release/host/` | `dev.clipboard.app.dev` / `~/Library/Logs/Clipboard/dev/host/` |
| 视觉标识 | 标准图标与菜单栏图标 | 应用图标右下角带橙色 `DEV` 角标，菜单栏显示 `DEV` |

- `make dev` 按当前工作区可执行文件的完整路径精确结束旧开发版进程，不会停止或覆盖日常使用的正式版。
- 两版并行运行时共享同一个 macOS 系统剪贴板；并行验收请使用合成文本、链接或图片，避免把日常剪贴板内容带入开发版测试环境。

## 本机诊断日志

基于 `kirktools/pkg-logging`（`KirkLogging`）提供异步写入、自动轮转、按时间/模块/级别筛选导出 JSON 与一键清除功能，可在「设置 → 本机诊断日志」中管理：

- **默认状态**：正式版默认关闭的是**本机诊断日志文件**（`~/Library/Logs/Clipboard/release/host/`），开发版默认开启。系统统一日志（OSLog）仍会记录少量脱敏后的状态事件（如监听启停、跳过原因、存储错误码），不会写入用户剪贴板内容。
- **记录范围**：监听启停、剪贴板权限状态变化、跳过原因（暂停/敏感标记/自写回/瞬态恢复）、存储失败及关键操作耗时。
- **脱敏边界**：所有日志字段限定为编译期静态标识、时间戳、随机操作编号和耗时数值；诊断文件、导出 JSON 与 OSLog 均不包含剪贴板正文、链接、图片、收藏标题、内容哈希、凭据、个人路径或原始错误文本。

## 签名、打包与发布

`scripts/build.sh` 在构建 Release 时会对复制进 App 的可执行文件执行 `strip -S` 移除调试符号中的本机绝对路径，再执行签名；`scripts/package.sh` 在打包 DMG 与 ZIP 前后均会运行 `codesign --verify --strict`、个人路径残留扫描（命中仅报告包内文件与问题类型）以及资源完整性校验，确保安装包包含主许可证（`LICENSE`）、依赖许可证（`LICENSE-KirkLogging`、`LICENSE-CocoaLumberjack`）和依赖隐私清单（`CocoaLumberjack_CocoaLumberjack.bundle/PrivacyInfo.xcprivacy`）。

当前签名与分发策略：

1. **免费分发（不购买 Apple Developer ID 证书，不公证）**：当前面向开源免费分发，`dist/packages/manifest.json` 标注 `"notarized": false`。其他机器首次打开下载的安装包时，macOS Gatekeeper 会提示无法验证开发者，需在「系统设置 → 隐私与安全性」中点击「仍要打开」（或在访达中按住 `Control` 点击应用选择「打开」）。
2. **ad-hoc 签名（默认本地兜底）**：`manifest.json` 标注 `"signing": "adhoc"`。无需证书即可在本地构建和运行；每次重新构建会变化代码哈希（cdhash），可能触发系统重新询问剪贴板隐私权限。
3. **项目固定发布证书（CI 正式发布）**：
   - 运行 `make signing-prepare` 在本机 `.local/signing/release/` 生成项目专用的自签名发布证书（不进入源码仓库），运行 `make signing-ci` 将其上传到 GitHub Actions Secrets（`CLIPBOARD_RELEASE_P12_BASE64` / `CLIPBOARD_RELEASE_P12_PASSWORD`）。
   - Release 工作流通过 `scripts/release-signing.py runner` 在临时钥匙串中导入固定证书并强制要求 `REQUIRE_STABLE_SIGNING=1` 与证书签名（`--options runtime`、`manifest.json` 标注 `"signing": "certificate", "notarized": false`），结束时自动销毁临时钥匙串。
   - 开发版可通过环境变量 `DEV_SIGNING_IDENTITY` 或被 Git 忽略的 `.local/dev-signing-identity` 指定本地证书身份。

### 版本与发布说明

- **日常发版只需 `make release`**：遵循 SemVer（`BUMP=patch|minor|major`，默认 `patch`），负责检查干净的 `master` 与远端同步、运行 `make check` 与 `make test`、递增 `Resources/Info.plist` 版本号与构建号、提交版本、创建注释标签并原子推送 `master` 与标签（首个通过 `make release` 发布的公开版本为 `0.1.1` / `v0.1.1`）。
- **GitHub Actions 自动化**：
  - **CI（`.github/workflows/ci.yml`）**：普通 push 与 PR 触发，从干净检出解析锁定依赖（`Package.resolved`），运行 `make check`、`make test` 与 `make package` 校验并上传构建产物。
  - **Release（`.github/workflows/release.yml`）**：推送 `vX.Y.Z` 标签触发，校验标签与 `Resources/Info.plist` 一致，运行检查、测试与 `make package`（自动校验实际 ZIP 与挂载 DMG 内的签名、许可证、隐私清单及零本机路径残留），随后创建 GitHub Release 并上传 DMG、ZIP、`manifest.json` 与 `SHA256SUMS`。若工作流失败重跑，沿用原标签覆盖上传产物。
  - 若在仓库配置了 `CLIPBOARD_RELEASE_P12_BASE64` 与 `CLIPBOARD_RELEASE_P12_PASSWORD` Secrets，Release 工作流会自动导入临时钥匙串进行稳定证书签名并在结束时销毁；若未配置且未设置变量 `REQUIRE_STABLE_SIGNING=1`，则按免费 ad-hoc 签名发布。

```sh
make release-dry-run BUMP=patch  # 只读预览版本号、构建号与标签，不改文件、不联网
make release BUMP=patch          # 提交版本、打标签并原子推送，由 GitHub Actions 自动分发
```

## 与 Hotkey 配合

Clipboard 是独立应用，从菜单栏即可完整使用。如需全局快捷键呼出面板：

1. 在 Hotkey 的「应用快捷切换」中添加 `Clipboard.app`（或开发版 `Clipboard Dev.app`）并绑定快捷键。
2. 状态行为：
   - **尚未运行**：按下快捷键拉起 Clipboard 并自动打开历史面板。
   - **已常驻但面板关闭**：按下快捷键激活 Clipboard 并打开历史面板。
   - **面板正在显示**：按 `Esc` 或 `↩` 立即收起面板并交回焦点；由于 macOS 会拒绝针对 `LSUIElement` 应用的 `NSRunningApplication.hide()` 请求，若需在 Hotkey 中再次按同一快捷键收起面板，需 Hotkey 在 `hide()` 被拒绝时回退至 `openApplication` 触发 reopen 切换（Clipboard 已内置 reopen 切换支持）。
3. **划词翻译兼容**：内置 120ms 稳定防抖窗口，Hotkey 划词翻译临时复制选中文字并迅速恢复原剪贴板时，瞬态内容不会混入历史记录。
