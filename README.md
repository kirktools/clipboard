# Clipboard

[官网](https://kirktools.github.io/clipboard/) · [下载最新版本](https://github.com/kirktools/clipboard/releases/latest) · [更新日志](https://github.com/kirktools/clipboard/releases)

原生 macOS 菜单栏剪贴板历史与长期收藏工具，基于 Swift、SwiftUI 与 AppKit 实现，仅依赖共享日志包 `kirktools/pkg-logging`（锁定于 `Package.resolved`）。默认界面语言为简体中文。

## 功能概览

- **最近历史**
  - 常驻菜单栏，自动记录纯文本、网页链接（`http`/`https`）和图片（支持截图、PNG/JPEG/HEIC/GIF/WebP/TIFF、浏览器/聊天软件复制图片及访达单个图片文件），重启后保留。
  - 默认保留最近 50 条（可在设置中调整为 10–500 条）；重复复制同一内容时更新最近时间并置顶，不产生重复记录。
  - 面板支持拖动移动、自由缩放（记住位置与尺寸）和钉住窗口（`⌘P`，方便连续多条复制），支持按文本、链接与条目名称实时搜索。
  - 键盘优先操作：`↑`/`↓` 选择，`↩` 复制回系统剪贴板（未钉住时自动关闭面板），`⌘1`/`⌘2` 切换「最近 / 收藏」，`⌘D` 收藏或取消收藏，`⌘P` 钉住/取消钉住，`⌘⌫` 删除，`Esc` 关闭。
- **长期收藏**
  - 最近记录可一键收藏；「收藏」有独立入口，支持改名、搜索、取消收藏和再次复制。
  - 收藏跨重启保留，不占最近历史条数；即使历史因上限被淘汰或用户清空最近，收藏条目及图片依然完整保留。
- **隐私与联网边界**
  - 所有历史、收藏与图片缓存仅保存在本机，不上传云端，不接入任何统计分析。
  - 提供「暂停记录」入口，暂停期间不写入新历史。
  - 自动跳过明确标记为敏感、临时或自动生成的剪贴板内容（如 `org.nspasteboard.ConcealedType`、`TransientType`、`AutoGeneratedType` 等）。但并非所有密码管理器都会写入此类标记，**未标记的敏感剪贴板内容仍可能被记录**，敏感操作前建议暂停记录。
  - 日常使用不联网；**仅在用户主动点击菜单栏「检查更新…」时**连接 GitHub 官方发布接口检查与下载更新包。
  - 兼容 macOS 15.4+ 剪贴板访问行为（`NSPasteboard.accessBehavior`），在设置中展示当前授权状态。

## 安装与应用内更新

- **首次安装（DMG）**：从[官网](https://kirktools.github.io/clipboard/)或 [GitHub Releases](https://github.com/kirktools/clipboard/releases/latest) 下载 `Clipboard-macos-arm64.dmg`（或带版本号的 `Clipboard-<version>-macos-arm64.dmg`），拖入「应用程序」文件夹。
  - 当前使用项目固定自签名证书签名，**不购买 Apple Developer ID 证书，也未做 Apple 公证**（`manifest.json` 标注 `"notarized": false`）。
  - 首次打开若遇到系统安全提示，请在「系统设置 → 隐私与安全性」中点击「仍要打开」（或在访达中按住 `Control` 点击应用选择「打开」），请勿关闭系统 Gatekeeper。
- **应用内更新（ZIP，用户确认）**：
  - 正式版在菜单栏提供「检查更新…」，读取 GitHub 最新正式版，按当前架构选择 `Clipboard-<version>-macos-<arch>.zip` 与 `SHA256SUMS`。
  - **经用户点击「更新并重启」确认后**才下载安装；安装前严格校验 SHA-256、ZIP 安全目录、版本号、Bundle ID（`dev.clipboard.app`）、芯片架构与**可验证的同发布者证书**，并在同盘备份旧版后原子交换；任意步骤失败均保留旧版或自动回滚。
  - 若当前为 ad-hoc 本地构建（无法验证发布者身份）、从临时隔离路径运行或安装目录不可写，应用内替换会自动停用，仅提示新版本并提供「打开官方下载页」手动更新（不会把 SHA-256 或 ad-hoc 签名当作发布者身份验证）。
  - 开发版（`Clipboard Dev.app`）继续通过 `make dev` 更新。

## 日常开发与构建

需要 macOS 14+ 与 Swift 6 / Xcode Command Line Tools。

```sh
make dev                         # 仅重启当前工作区的开发版 dist/dev/Clipboard Dev.app
make test                        # 运行单元测试与集成测试
make check                       # 脚本语法、Info.plist、diff 与编译检查（不启动应用）
make build                       # 仅构建开发版（CONFIG=debug）
make build CONFIG=release        # 仅构建发布版（dist/release/Clipboard.app）
make package                     # 生成本地 Release 安装包（DMG/ZIP/校验清单，不发布）
make release-dry-run BUMP=patch  # 仅预览 SemVer 递增与本地发布条件（不改文件、不联网）
make site | site-check | site-preview  # 构建、检查或本地预览静态官网
```

静默常驻启动（仅驻留菜单栏，不弹出面板）：

```sh
open "dist/dev/Clipboard Dev.app" --args --background
```

### Dev 与正式版隔离

| 项目 | 正式版（Release） | 开发版（Dev） |
| --- | --- | --- |
| 应用包 | `dist/release/Clipboard.app` | `dist/dev/Clipboard Dev.app` |
| Bundle ID / 签名标识 | `dev.clipboard.app` | `dev.clipboard.app.dev` |
| 数据目录（设置/历史/收藏/图片） | `~/Library/Application Support/Clipboard/` | `~/Library/Application Support/Clipboard-dev/` |
| 诊断偏好域与日志目录 | `dev.clipboard.app` / `~/Library/Logs/Clipboard/release/host/` | `dev.clipboard.app.dev` / `~/Library/Logs/Clipboard/dev/host/` |
| 视觉标识 | 标准图标与菜单栏图标 | 应用图标右下角带橙色 `DEV` 角标，菜单栏显示 `DEV` |

- `make dev` 按当前工作区可执行文件的完整路径精确结束旧开发版进程，不会停止或覆盖日常使用的正式版。
- 两版并行运行时共享同一个 macOS 系统剪贴板；并行验收请使用合成文本、链接或图片，避免把日常剪贴板内容带入开发版测试环境。

## 本机诊断日志

基于 `kirktools/pkg-logging`（`KirkLogging`）提供异步写入、自动轮转、按时间/模块/级别筛选导出 JSON 与一键清除功能，可在「设置 → 本机诊断日志」中管理：

- **默认状态**：正式版默认关闭的是**本机诊断日志文件**（`~/Library/Logs/Clipboard/release/host/`），开发版默认开启。系统统一日志（OSLog）仍会记录少量脱敏后的状态事件（如监听启停、跳过原因、存取错误码与更新检查状态），不会写入剪贴板内容。
- **记录范围**：监听启停、剪贴板权限状态变化、跳过原因（暂停/敏感标记/自写回/瞬态恢复）、存储失败、应用更新及关键操作耗时。
- **脱敏边界**：所有日志字段限定为编译期静态标识、时间戳、随机操作编号和耗时数值；诊断文件、导出 JSON 与 OSLog 均不包含剪贴板正文、链接、图片、收藏标题、内容哈希、凭据、个人路径或原始错误文本。

## 签名、发布与官网维护

`scripts/build.sh` 在构建 Release 时会对复制进 App 的可执行文件执行 `strip -S` 移除调试符号中的本机绝对路径，再执行签名；`scripts/package.sh` 在打包 DMG 与 ZIP 前后均会运行 `codesign --verify --strict`、个人路径残留扫描（命中仅报告包内文件与问题类型）以及资源完整性校验，确保安装包包含 `LICENSE`、`LICENSE-KirkLogging`、`LICENSE-CocoaLumberjack` 和 `CocoaLumberjack_CocoaLumberjack.bundle/PrivacyInfo.xcprivacy`。

1. **项目固定发布证书（CI 正式发布）**：
   - 运行 `make signing-prepare` 在本机 `.local/signing/release/`（已由 `.gitignore` 忽略）生成项目专用自签名发布证书；运行 `make signing-ci` 将其上传到 GitHub Actions Secrets（`CLIPBOARD_RELEASE_P12_BASE64` / `CLIPBOARD_RELEASE_P12_PASSWORD`）。
   - Release 工作流通过 `scripts/release-signing.py runner` 在临时钥匙串中导入证书并强制要求 `REQUIRE_STABLE_SIGNING=1` 与证书签名（`--options runtime`、`manifest.json` 标注 `"signing": "certificate", "notarized": false`），结束时销毁临时钥匙串。
   - 本地开发默认使用 ad-hoc 兜底，也可通过 `DEV_SIGNING_IDENTITY` 或 `.local/dev-signing-identity` 指定本地证书身份。
2. **日常发版（只需 `make release`）**：
   - `make release [BUMP=patch|minor|major]` 检查干净的 `master` 与远端同步、运行 `make check` 与 `make test`、递增 `Resources/Info.plist` 版本号与构建号、提交版本、创建注释标签并原子推送 `master` 与标签。
   - 推送 `vX.Y.Z` 标签触发 `.github/workflows/release.yml`：校验标签与版本一致、运行检查/测试/打包（含 ZIP 解压与 DMG 挂载抽检），发布 GitHub Release（DMG 用于首次安装、ZIP 用于更新，均提供版本文件名、稳定别名及 `SHA256SUMS` / `manifest.json`），成功后自动触发 `.github/workflows/pages.yml` 部署该标签源码对应的官网。失败重跑沿用原标签。
   - 普通 push 与 PR 触发 `.github/workflows/ci.yml`（依赖锁校验、检查、测试、打包校验）与 `.github/workflows/site-check.yml`（仅校验官网，不部署）。
3. **仅更新官网（不发新版本）**：
   - 本地通过 `make site` 构建、`make site-check` 校验、`make site-preview` 预览（默认 `http://127.0.0.1:4173`）。
   - 如需在不发布新应用版本的情况下仅更新官网内容，可在 GitHub Actions 中手动触发 `Deploy release website`（`.github/workflows/pages.yml`），选择 `mode = website` 并从 `master` 分支运行；官网下载链接仍会自动锁定到最新已发布的正式版标签。

## 与 Hotkey 配合

Clipboard 是独立应用，从菜单栏即可完整使用。如需全局快捷键呼出面板：

1. 在 Hotkey 的「应用快捷切换」中添加 `Clipboard.app`（或开发版 `Clipboard Dev.app`）并绑定快捷键。
2. 状态行为：
   - **尚未运行**：按下快捷键拉起 Clipboard 并自动打开历史面板。
   - **已常驻但面板关闭**：按下快捷键激活 Clipboard 并打开历史面板。
   - **面板正在显示**：按 `Esc` 或 `↩`（未钉住时）收起面板并交回焦点；由于 macOS 会拒绝针对 `LSUIElement` 应用的 `NSRunningApplication.hide()` 请求，若需在 Hotkey 中再次按同一快捷键收起面板，需 Hotkey 在 `hide()` 被拒绝时回退至 `openApplication` 触发 reopen 切换（Clipboard 已内置 reopen 切换支持）。
3. **划词翻译兼容**：内置 120ms 稳定防抖窗口，Hotkey 划词翻译临时复制选中文字并迅速恢复原剪贴板时，瞬态内容不会混入历史记录。
